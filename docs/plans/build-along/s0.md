### Where the plan's assumptions differ

1. **`stepCountIs` is now `isStepCount`** in `ai` 7. `stepCountIs` is still exported, but only as an alias
   (`isStepCount as stepCountIs`), and the `@cloudflare/ai-chat` README uses `isStepCount(5)`. Lessons
   should teach `isStepCount`.
2. **"Learner's own key in their own gateway (BYOK)" needs the gateway to exist first.** `createAI` routes
   every call, Workers AI `@cf/…` ids included, through a gateway. It defaults to `"default"`, which
   Cloudflare creates on first use. The plan's `id: "klippy"` must be created in the dashboard first,
   otherwise every call fails with 2001. A catalog id like `anthropic/claude-haiku-5.5` uses the BYOK key
   stored on that gateway when there is one. Without one it uses **Unified Billing** (Cloudflare bills the
   account) if that's enabled, and otherwise fails. The first lesson that calls Claude needs an explicit
   step: create gateway `klippy`, store the Anthropic key on it, then run. Otherwise use `id: "default"`.
3. **The one-line Workers AI switch also goes through the gateway** (point 2). The free switch is
   `ai("@cf/zai-org/glm-4.7-flash")` (the id in Cloudflare's own `createAI` examples). It needs the same
   gateway to exist. `glm-4.7-flash` is a reasoning model: our run spent 11.6 s on 914 characters of
   reasoning before any text arrived. Either render reasoning parts in the island, or pass
   `reasoningEffort: "low"` (a documented `createAI` option; not tried).
4. **There is no `remix new` → Workers path in the installed docs.** Guide 11 ("Files and Assets") is
   marked unfinished, and `remix/assets` (`createAssetServer`) needs Node's fs and esbuild at request
   time. It can't run in a Worker. Bits solves this with a 400-line crawl (decision 002). The beginner
   setup below avoids that whole layer.
5. **`ai-gateway-provider` deprecated**: consistent with what's installed (not used).

## 1. Streaming into an island via a service binding

### The shape that works

```
browser island ──WebSocket /chat──▶ web Worker (Remix router, session) ──env.AGENT.fetch()──▶ agent Worker
   AgentClient{basePath:"chat"}        picks name = session "visitor"        routeAgentRequest → Klippy DO
   WebSocketChatTransport               rewrites URL to /agents/klippy/<name>   AIChatAgent.onChatMessage
   readUIMessageStream                                                           streamText → UI message stream
```

- The agent Worker has `"workers_dev": false` and no routes, so the service binding is its only way in.
  (Locally its own port answers too. Expected in dev.)
- The browser never names the agent instance. `AgentClient({ basePath: "chat" })` connects to `/chat`,
  and the server decides the instance (the "Server-Side Instance Selection" pattern in
  `agents/docs/routing.md`).
- The WebSocket upgrade went through the Remix router, the session middleware and the service binding,
  and came back as a 101 with the socket intact. Nothing wrapped or broke it.
- **Server-first history**: the home action fetches
  `env.AGENT.fetch("https://agent/agents/klippy/<name>/get-messages")` (an endpoint built into
  `AIChatAgent`) and passes the messages as plain-JSON island props. A reload shows the saved
  conversation before any JS runs.

### Key snippets (the lines a lesson needs)

Agent (`apps/agent/src/index.ts`):

```ts
export class Klippy extends AIChatAgent<Env> {
  async onChatMessage(_onFinish: unknown, options?: { abortSignal?: AbortSignal }) {
    const ai = createAI({ binding: this.env.AI, id: "klippy" }); // gateway must exist (see above)
    const result = streamText({
      model: ai("anthropic/claude-haiku-5.5"), // or "@cf/zai-org/glm-4.7-flash": the free switch
      system: "You are Klippy, a short, friendly assistant.",
      messages: await convertToModelMessages(this.messages),
      abortSignal: options?.abortSignal,
    });
    return result.toUIMessageStreamResponse();
  }
}
export default {
  async fetch(request: Request, env: Env) {
    return (await routeAgentRequest(request, env)) ?? new Response("Not found", { status: 404 });
  },
} satisfies ExportedHandler<Env>;
```

Web Worker forwarding (`apps/web/app/router.tsx`):

```tsx
router.map(routes.chat, (context) => {
  if (context.request.headers.get("Upgrade") !== "websocket") {
    return new Response("Expected a WebSocket", { status: 426 });
  }
  let url = new URL(`/agents/klippy/${agentName(context.session)}`, context.request.url);
  return env.AGENT.fetch(new Request(url, context.request)); // service binding
});
```

Island stream loop (`apps/web/app/public/chat.tsx`, the part D9 explains):

```tsx
export const Chat = clientEntry("/assets/chat.js#Chat", function Chat(handle: Handle<{ initial: Message[] }>) {
  let messages = handle.props.initial as UIMessage[];
  let transport: WebSocketChatTransport | undefined;
  function connect() { // browser only: setup also runs on the server
    transport ??= new WebSocketChatTransport({
      agent: new AgentClient({ agent: "Klippy", basePath: "chat", host: location.host }),
    });
    return transport;
  }
  async function send(text: string) {
    messages = [...messages, { id: crypto.randomUUID(), role: "user", parts: [{ type: "text", text }] }];
    handle.update();
    let stream = await connect().sendMessages({ chatId: "klippy", messages, abortSignal: undefined, trigger: "submit-message" });
    let index = messages.length;
    for await (let reply of readUIMessageStream({ stream, terminateOnError: true })) {
      messages = [...messages.slice(0, index), reply]; // one assistant message, growing
      handle.update();
    }
  }
  return () => (/* <ol> of messages, a native <form> whose submit handler calls send() */)
})
```

### What was observed

- Scripted model (`MockLanguageModelV4` from `ai/test`, 150 ms per word), sampled every 200 ms in the
  DOM: `"" → "Hello " → "Hello from " → … → full text` by 1.4 s. A second turn worked the same way.
- Workers AI `@cf/zai-org/glm-4.7-flash`, called **directly** through `workers-ai-provider` because the
  gateway leg was blocked (above). Text length went 23 → 59 → 84 → … → 287 characters, in 100 ms steps,
  between 11.6 s and 12.4 s. The agent log reported `finishReason: "stop"`, 738 input / 258 output tokens,
  and 914 characters of reasoning.
- No browser console errors. With the model failing, the island showed `An error occurred.`
  (`toUIMessageStreamResponse` masks error text by default) instead of hanging.
- **Not run:** a live Claude reply, `needsApproval` tool approval, stream resume after a dropped socket,
  a deployed (non-local) service binding, and the `latest` bump of any package.

## 2. Smallest Remix-on-Workers setup a beginner can follow

The idea: don't run Remix's asset server at all. Give each island a **public URL** as its entry id. Bundle
the browser files once with esbuild into `public/assets/`, and let Workers Static Assets serve them.
`render()` without `assets` accepts public-URL entries: the render-middleware README says "Omit it when
client entries already use public URLs", and the `clientEntry` docs give the `"/js/module.js#ExportName"`
format.

File tree (both apps; nothing else is needed):

```
klippy/
  package.json                 { "private": true, "type": "module" }
  pnpm-workspace.yaml          packages: [apps/*, packages/*] + allowBuilds (gotcha 1)
  apps/agent/
    package.json  tsconfig.json  wrangler.jsonc  src/index.ts
  apps/web/
    package.json               scripts.build:client = the esbuild line below
    tsconfig.json              jsx: react-jsx, jsxImportSource: remix/component
    wrangler.jsonc             main, assets.directory, build.command, services, d1_databases
    app/worker.ts              export default { fetch: (r) => router.fetch(r) }
    app/routes.ts              route({ home: get("/"), chat: get("/chat") })
    app/router.tsx             createRouter({ middleware: [session(...), render()] }) + actions
    app/public/entry.ts        run({ loadModule: (url, name) => import(url).then((m) => m[name]) })
    app/public/chat.tsx        the island
    public/assets/             esbuild output (gitignore it)
```

Steps:

1. `pnpm add remix agents ai` and `pnpm add -D wrangler esbuild typescript` in `apps/web`.
2. `tsconfig.json`: `"jsx": "react-jsx", "jsxImportSource": "remix/component"`. **Wrangler's bundler reads
   this.** Without it the page fails with `ReferenceError: React is not defined`.
3. `wrangler.jsonc`:
   ```jsonc
   { "name": "klippy-web", "main": "app/worker.ts", "compatibility_date": "2026-11-01",
     "assets": { "directory": "public" },
     "build": { "command": "pnpm build:client" },
     "services": [{ "binding": "AGENT", "service": "klippy-agent" }] }
   ```
4. `build:client`:
   `esbuild app/public/entry.ts app/public/chat.tsx --bundle --splitting --format=esm --minify --outdir=public/assets --jsx=automatic --jsx-import-source=remix/component`.
   `--splitting` gives one shared chunk for `remix/component`, so the entry and the islands share one
   runtime. Every new island is one more file on this line.
5. In the document, add `<script type="module" src="/assets/entry.js"></script>`. `entry.ts` calls `run()`
   with a plain `import(moduleUrl)` (the multiple-import-maps polyfill isn't needed: no import maps).
6. `pnpm wrangler types`, then `wrangler dev` (it runs `build.command` first). `wrangler deploy` works the
   same way. No custom Worker bundler, no `no_bundle`, no manifest.

Costs of the simple path (say them in the lesson):

- Bundles aren't fingerprinted (`/assets/chat.js` keeps its name), so leave caching at the default or
  add a `?v=` per deploy. Bits' crawl exists to get immutable hashed URLs. A beginner doesn't need that.
- Sizes measured: `chat.js` 260 KiB (72 KiB gz, `agents/client` + `ai`), shared chunk 105 KiB (33 KiB gz),
  `entry.js` 118 B.
- The server imports the island module to render it, so `agents/client` and `ai` land in the web Worker
  too (724 KiB upload / 150 KiB gz in total). Acceptable; it fits easily in the limits.
- `remix doctor` passes environment and project, and warns `Root route map is missing action controller
  app/actions/controller.tsx` because the spike mapped inline handlers. The course should use the
  `app/actions/<area>/controller.tsx` layout and then rerun doctor.

## 3. The D1 driver for `remix/data-table`

The same suite ran against each driver, each on its own fresh Miniflare D1 (`miniflare` 5, with
`convertV4MiniflareOptions`, as in bits' `packages/db/test/d1.ts`). Schema: `users` (text PK, unique
email, boolean and JSON columns) and `notes` (autoincrement PK, FK `on delete cascade`).

| Check | bits `packages/db` | `@sdxc/data-table-d1` 2026.10.24 | `@pitlane/data-table-d1` 0.3.0 |
|---|---|---|---|
| create with a JSON array value | ok (stringifies objects) | ok | **throws** `D1_TYPE_ERROR: Type 'object' not supported` |
| create + find, `returnRow`, autoincrement `insertId`, `createMany` + `returnRows` | ok | ok | ok (JSON pre-stringified) |
| unique violation rejects, FK cascade delete, count/exists, `inList`/`like`/orderBy/limit/offset, `update`, raw `db.exec(sql\`…\`)` | ok | ok | ok |
| boolean column reads back as `boolean` | **no** (`0`; bits decodes in each table's `afterRead`) | yes | no (`0`) |
| JSON column reads back decoded | **no** (string; same) | yes | no (string) |
| upsert with `{ update: {...} }` | ok | ok | **wrong**: binds `[3,"a",1,3]` for `values (?,?,?) … do update set n = ?`, so the update value lands in the id column and inserts a stray row (bits binds `["a",1,3,3]`) |
| `db.transaction()` | refuses (`D1UnsupportedError`) | **runs non-atomically**: an earlier write survives the throw | refuses (opt-in `unsafe-nonatomic`) |
| atomic multi-write | `db.batch([d1.prepare().bind()])`, rolled back on FK failure | no helper (README points to single statements or a DO) | `db.batch([sql\`…\`])`, rolled back |
| `updateMany` with orderBy+limit | refuses | works (non-atomic scope) | refuses |

Also run: bits' driver (copied verbatim) inside the web Worker under `wrangler dev`, against a local D1
made with `wrangler d1 migrations apply DB --local`. `GET /notes` created a row with RETURNING and
counted 1 → 2 across two requests. `pinned` came back as `1`, which confirms the decode gap.

### Recommendation: publish bits' driver (lane P), with two changes

Why ours:

- It refuses `transaction()` loudly and gives `batch()`. For a course that teaches "D1 has no
  interactive transactions", that's the honest API. sdxc's default silently loses atomicity, and a
  learner can't see it happen.
- It has a stable peer range (`^3.1.0`). sdxc pins `remix: 3.1.0` exactly, which would trip the weekly
  latest job on the first `remix` 3.1.x/3.2.
- The compiler is vendored verbatim from `@remix-run/data-table-sqlite@1.0.0`, the version `remix` 3.1.0
  ships. I diffed it: only the header and import lines differ. Pitlane's copy comes from `0.6.0`, and its
  upsert bug is the kind of drift that causes.
- The bits suite passes, and bits already runs it in production.

Changes lane P should make before publishing:

1. **Decode by column type in the driver.** Read `boolean()` as `true`/`false` and `json()` with
   `JSON.parse`, from both selects and RETURNING rows, as sdxc does. Bits does this per table in
   `afterRead`, but a learner shouldn't have to. Keep bits' `afterRead` working, so decoding has to be
   idempotent, or bits drops its hooks.
2. **Type the binding structurally** (a `D1Like` with `prepare`/`batch`), rather than importing
   `@cloudflare/workers-types/index.ts`. A Worker app gets its D1 types from `wrangler types`, and the
   spike needed a 3-line shim to compile against them.

Package size: `driver.ts` 206 + `database.ts` 35 + `types.ts` 7 lines, plus the 500-line vendored compiler
(MIT, Shopify notice kept). The `meter.ts` Server-Timing wrapper stays in bits.

Fallback if P doesn't happen: `@sdxc/data-table-d1`. It passed every check. The lessons would then need
to say that `transaction()` isn't atomic on it and must never be used, and the lockfile would have to
follow its exact `remix` peer.

## Gotchas found (each one cost time in the spike)

1. **pnpm 11 blocks build scripts and adds release-age excludes.** The first install ended with
   `ERR_PNPM_IGNORED_BUILDS` for esbuild/workerd and rewrote `pnpm-workspace.yaml` with a placeholder
   `allowBuilds:` block (values "set this to true or false"), plus `minimumReleaseAgeExclude` entries for
   the freshly published `agents`, `ai`, `wrangler` and workerd. Adding a second `allowBuilds:` key made the
   YAML invalid ("duplicated mapping key"). After fixing it, the esbuild bin shim still ran the native
   binary through Node (`SyntaxError: Invalid or unexpected token`) until a clean
   `rm -rf node_modules && pnpm install`. Lesson A1 should ship `pnpm-workspace.yaml` with
   `allowBuilds: { esbuild: true, workerd: true }` from the start, or pin pnpm 10 with
   `packageManager` + corepack, as the plan says.
2. **`wrangler types` makes vars literal types.** `"MODEL": "stub"` became `MODEL: "stub"`, so any other
   value failed `tsc`. Use `wrangler types --strict-vars=false` for vars meant to be switched.
3. **`createAI` has no gateway-less mode**, and its errors go to the Worker log, not the reply. Every
   model id goes through the gateway (2001 if it doesn't exist). The island only sees
   "An error occurred.", so the first "call Claude" lesson needs a "check `wrangler dev` output" step.
4. **`ai(id)` wants a literal-shaped id.** A plain `string` from env doesn't typecheck. Cast it to
   `` `${string}/${string}` `` or keep the id in code (simpler for the one-line switch).
5. **Island setup runs on the server too.** Create `AgentClient` lazily, on the first event (or in a
   browser-only hook), never at setup. Props must be plain JSON, so pass the message list, not
   `UIMessage` class instances.
6. **The dev registry is shared across every local `wrangler dev`.** Service bindings resolve by Worker
   name through `~/.config/.wrangler/registry`. Other lanes running a `klippy-agent` at the same time
   would collide. Each lane should use a distinct Worker name, or one `wrangler dev -c a -c b` process.
7. **Rebuild after changing `tsconfig.json`.** `wrangler dev` doesn't watch it, so the JSX fix needed a
   restart.
8. **A reasoning model looks frozen.** With `glm-4.7-flash`, text-only rendering showed nothing for 11 s.
   Show reasoning parts, or a "thinking" state while the message has only reasoning.
9. Upload sizes from `wrangler deploy --dry-run`: agent 3,570 KiB / 690 KiB gz, which includes `ai/test`
   for the spike's scripted model; drop that in the course. Web 724 KiB / 150 KiB gz.
